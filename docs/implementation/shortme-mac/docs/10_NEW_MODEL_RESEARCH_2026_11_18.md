**Scope:** documentary GitHub/HF/Apple findings only; no repo clones, Apple Silicon inference runs or independent clip-quality benchmarks were performed in this package. 'Better' means plausible improvement per functional task, not a proved viral-video score. This adds to original docs 01–09 and does NOT relax V4 requirements.

## B. Why this changes original Mac plan

**SoundAnalysis** is Apple's own integrated sound classifier; the official docs explicitly mention laughter and applause among 300+ categories. Start with it, apply multiple windows, smoothing/hysteresis, and log timestamp confidence. It detects sound classes, **not jokes**; false positives (game sounds, canned laughter, cheering) require negative controls and context checks. This avoids burning GPU time running a language model over an hour of audio merely to find laughter. [Apple official](https://developer.apple.com/documentation/soundanalysis/classifying-sounds-in-an-audio-file).

**Marlin-2B** is interesting because it generates temporal video descriptions and can answer 'find event X in source'; clipmunk already documents it on sub-16 GiB Apple Silicon. [`marlin-mlx`](https://github.com/Hook12aaa/marlin-mlx) is a distinct C++ inference engine that claims macOS 26+ and notes **real-video frame bugs** in earlier benchmarks: don't assume synthetic throughput equates to correct video. Separate model architecture, frame preprocessing, aspect ratio, FPS/PTS, tokenization, image position encoding, video timestamp results all need tests. Its code is MIT and model card lists Apache-2.0; review exact bundled tree and revisions.

**Qwen3.5-4B vs Gemma 4 E4B**: Both the **official Qwen3.5-4B** and **official Gemma 4 E4B** model weights are listed as **Apache-2.0** (verify any third-party quantized variant independently); do not carry over old Gemma-generation licensing assumptions. Google estimates ~4.5 GB for E4B Q4_0 and ~2.9 GB for E2B Q4_0 as generic inference memory including a specified margin, **NOT** measured unified macOS total process peak. Another 16 GiB safety margin is still needed for OS, decoded frames, KV/cache and rendering. Source: [Google overview](https://gemma.ai/models/gemma-4/). Qwen3.5 4B is described with vision encoder in official [HF card](https://huggingface.co/Qwen/Qwen3.5-4B), and supported by [vllm-metal](https://github.com/vllm-project/vllm-metal/blob/main/docs/supported_models.md). Community comparisons disagree about which small VLM 'sees' better; in [this Reddit report](https://www.reddit.com/r/LocalLLaMA/comments/1sedoqh/gemma4_e4b_models_vision_seems_to_be_surprisingly/) Gemma E4B underperformed Qwen3.5-4B, while [another user](https://www.reddit.com/r/LocalLLaMA/comments/1staxnq/gemma_4_beats_qwen_35_update_and_qwen_36_27b/) found Gemma better for classification. These are **not comparable ShortMe datasets**.

**ASR:** FluidAudio lists Parakeet **Ultra** (recommended), v3 and Redux multilingual Core ML with ~25 European languages including German and English. Ultra was added September 2026 and beats v3 in the published FLEURS 24-language aggregate (11.67% vs 14.81% WER); this is NOT a German podcast-specific result. It publishes hardware benchmarks, but reproducing them on an actual 16 GiB user's Mac is required. Apple SpeechAnalyzer should be a branch only when OS / language model available; do not infer that '42x realtime' from a separate repo applies universally. Proper nouns, interjections and overlapping talk are not solved by raw WER alone. The Qwen forced aligner can produce zero-duration words according to an [upstream issue](https://github.com/QwenLM/Qwen3-ASR/issues/197), so bounds must be validated and cannot be trusted blindly.

**CLAP2** ([repo](https://github.com/LAION-AI/clap2)) claims five audio-text model sizes (27M–340M) and says weights are Apache-2.0; use only if needed after Apple audio test. [`clap.cpp`](https://github.com/gorse-io/clap.cpp) is a pure C++ audio embedding implementation; verify the specific selected checkpoint and conversion, not just the repository license. YAMNet is an alternative smaller fixed AudioSet label classifier, but model packing and Core ML/ONNX conversion fidelity must be measured.

## C. New repositories worth reading, with discriminating value

- [`ngoldbla/clipmunk`](https://github.com/ngoldbla/clipmunk): real Mac app combining Parakeet/CoreML, local Gemma 4 E2B, Marlin-2B and face tracking. **Reference implementation**, not proved V4-equivalent, no full-source V4 quality evidence.
- [`mutonby/shortcast`](https://github.com/mutonby/shortcast): actual SwiftUI + Swift/MLX video clipping with Gemma 4 E4B clip watcher, Qwen3.5 director alternative and AVFoundation; primarily architecture reference.
- [`Yuu-yu09/clipper`](https://github.com/Yuu-yu09/clipper): effective design claim 'LLM is ranker, never finder'; uses signal-based energy/pitch/laughter candidate detection before LLM. Borrow *principle*, not unverified results.
- [`gnilobaiter/clipgen`](https://github.com/gnilobaiter/clipgen): per-window/long-form transcript, independent YAMNet laughter/scream lane, timeword alignment, transcript caching. Windows-CUDA pieces are not Mac engine dependencies.
- [`YashvanthSankar/choco.video`](https://github.com/YashvanthSankar/choco.video): Rust engine with a locally-built FFmpeg component, support for Apple speech; claimed measured M3 Pro throughput from author, not reproduced. Has eval CLI/human clip ranking design.
- [`markksantos/HookCut`](https://github.com/markksantos/HookCut): macOS podcast highlight export to FCPXML/Premiere XML; interesting for creator-editable handoff, but often transcript-first rather than full visual V4.
- [`yeliudev/VideoMind`](https://github.com/yeliudev/VideoMind) and [`TencentARC/TimeLens`](https://github.com/TencentARC/TimeLens): active temporal localization research, larger/unvalidated Mac runtime; learn investigation algorithms, not default runtime.
- [`Aseiel/VideoHighlighter`](https://github.com/Aseiel/VideoHighlighter): multimodal rule engine/feature causality design; **AGPL-3.0 code**, not blindly suitable for proprietary reuse.
- [`LAION-AI/clap2`](https://github.com/LAION-AI/clap2): candidate modern zero-shot audio events, exact model-specific integration needed.

## D. What not to assume

1. No public benchmark currently proves which stack best finds funny ShortMe clips. ImageQA, Video-MME, WER, AudioSet and human publishability measure different things.
2. Real life 16GB ≠ 16GB available for Metal. Every selected model needs observed peak RSS, Metal allocated size, swap behavior and unload/reload tests.
3. `Marlin-2B` dense captions do **not** subsume V4's semantic retrieval requirement; test both or admit unverified parity.
4. Neither a VLM's image encoder nor a transcript can see a joke's entire audio+visual payoff without actual audio/frames and output replay.
5. Source timestamps from an AI are suggestions, never lawful measured cut-edge IDs without source PTS validation.
6. Model weights, adapters, converted binaries, dataset annotations and dependencies must each be licensed individually.
